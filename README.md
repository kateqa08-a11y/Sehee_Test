## Spec: Test Case Section

### Goal

Add a simple section to manage test cases in this repository README.

### User Story

As a QA beginner, I want to record test cases in a visible place so that I can practice writing requirements, expected results, and test status.

### Requirements

- The README must include a test case section.
- Each test case must have an ID.
- Each test case must include a scenario.
- Each test case must include an expected result.
- Each test case must include a status.

### Acceptance Criteria

- Given a user opens the README, when they scroll to the test case section, then they can see at least one sample test case.
- Given a test case is listed, when the user reads it, then they can understand the scenario and expected result.
- Given the test case has a status, when the user reviews it, then they can tell whether it is planned, passed, failed, or blocked.

### Open Questions

- Should test cases stay in README or move to a separate file later?
- What status values should be allowed?
- Should failed test cases require a linked GitHub issue?

### Tasks

- Add a test case section to README.
- Add a sample test case table.
- Commit the README change.
- Open a pull request.
